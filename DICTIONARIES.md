# Original char tokenizer dictionaries

This archive preserves the 13 original dictionaries from infra's `tokenizer/char/res/sources`, totaling 16,259,265 bytes. jieba supplies both segmentation and part-of-speech dictionaries; Norvig and THUOCL supply segmentation dictionaries. Original bytes are preserved, including BOMs, CR separators, frequency columns, and part-of-speech columns. infra's build scripts still perform cleanup and normalization.

Package: [dictionaries-3ebaa990eb35.tar.gz](dist/dictionaries-3ebaa990eb35.tar.gz), 6,520,187 bytes, generated by `python3 pack.py dictionaries`. Local sources reside directly under `assets/dictionaries/`. The archive contains `jieba_big.txt`, `count_1w.txt`, and `thuocl/`, without an extra wrapper directory. License files accompany the release from the root `licenses/` directory.

## Upload and integration order

Upload the complete snapshot following the root README, verify the attachments, then switch infra's build references before removing the 13 original files from infra. The original archival workflow kept builds on their existing paths until the package became available, avoiding downloads from unpublished URLs.

The external repository serves both `//tokenizer/char/res:seg_main_dat` and `//tokenizer/pos/res:pos_jieba_dat`. Update both consumers when migrating. Source dictionaries belong in the resources repository; builds continue to generate the existing `.dat` outputs without changing runtime library interfaces.

## MODULE.bazel configuration

After upload, add the following after the `http_archive` definition:

```python
http_archive(
    name = "char_dictionary_sources",
    sha256 = "3ebaa990eb3517eba32d2eeb2c1c67212d41f08936e44b235da0601fa7715e4d",
    urls = [
        "https://github.com/tersemind/resources/releases/download/infra-resources-2026-10-09/dictionaries-3ebaa990eb35.tar.gz",
    ],
    build_file_content = """
exports_files(["jieba_big.txt"], visibility = ["//visibility:public"])
filegroup(
    name = "sources",
    srcs = glob(["*.txt", "thuocl/*.txt"]),
    visibility = ["//visibility:public"],
)
""",
)
```

This is a fixed snapshot assembled by category, not an upstream archive with identical bytes. Individual jieba or THUOCL URLs cannot serve as fallback URLs for the combined archive. A mirror must host the exact same archive.

## Segmentation and part-of-speech build changes

For `seg_main_dat.srcs` in `tokenizer/char/res/BUILD.bazel`, replace `glob(["sources/**"])` with these external inputs, keeping the remaining build inputs, tools, and outputs unchanged:

```python
"@char_dictionary_sources//:sources",
"@char_dictionary_sources//:jieba_big.txt",
```

Set the dictionary source directory before the existing build command:

```python
cmd = """SEG_DICT_SRC_DIR="$$(dirname "$(location @char_dictionary_sources//:jieba_big.txt)")" python3 $(location build_seg_dict.py) $(location //tokenizer/char/tests:universal_tokenizer_dict_merge) $(@D)""",
```

Change the jieba label in both `srcs` and the command of `tokenizer/pos/res/BUILD.bazel` to `@char_dictionary_sources//:jieba_big.txt`. Then remove the exports_files entry for the old `sources/jieba_big.txt`, remove the main repository's migrated `sources/` data, and update its provenance documentation. When running `build_seg_dict.py` independently, set `SEG_DICT_SRC_DIR` explicitly or adjust its default to the downloaded snapshot directory.

## Local use

The archived source directory can be used from the infra root before upload or a new download:

```bash
source bd/paths/paths.sh && infra_load_paths "$PWD"
bazel build //tokenizer/char/tests:universal_tokenizer_dict_merge
SEG_DICT_SRC_DIR="$PWD/../resources/assets/dictionaries" \
  python3 tokenizer/char/res/build_seg_dict.py \
  bazel-bin/tokenizer/char/tests/universal_tokenizer_dict_merge \
  "$INFRA_TMP_ROOT/seg_dict/output"
```

After switching, build `//tokenizer/char/res:seg_main_dat` and `//tokenizer/pos/res:pos_jieba_dat` and compare generated outputs and segmentation/POS results before and after migration. The archived dictionaries must remain byte-for-byte identical to their original sources; migration must not alter merge weights or filtering logic.
